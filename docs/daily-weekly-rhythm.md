# Daily and Weekly Rhythm

The rhythm keeps live state current without turning the system into bureaucracy.

## Start of day

1. Resolve local date/timezone.
2. Open today's daily note.
3. Read the canonical TODO and active project state.
4. Confirm the main quest and at most one secondary stream.
5. Check blockers or time-sensitive external facts that could change today's plan.

## During work

Log significant events in chronological order:

- a build, fix, refactor, migration, or feature shipped or partially shipped;
- a material architecture, library, naming, or scope decision;
- a configuration, dependency, or infrastructure change;
- a debugging session that found a non-trivial cause;
- a significant file creation or deletion;
- a durable vault note created.

Pure read-only lookups and casual conversation do not need a log entry.

## Link inbox

Record incoming links immediately in the final `Links Inbox` section. Analyze them, add a link to any durable note created, then check them off. Never record a notification or external delivery as successful until its receipt is verified.

## Close of day

1. Reconcile active task state.
2. Process or explicitly defer unchecked links.
3. Promote durable decisions/learnings to atomic notes.
4. Write one-line outcome and next action for active projects.
5. Ensure the link inbox remains last.
6. Optionally mark the daily note closed after all intended captures are handled.

## Weekly review

- Outcomes verified, not activity volume.
- Decisions made and assumptions invalidated.
- Tasks that moved, stalled, or should be dropped by explicit decision.
- Repeated agent friction that justifies an instruction, skill, test, or hook.
- Security/ops anomalies, backup restore status, and upcoming credential rotations.
- One main outcome and optional secondary outcome for the next week.
