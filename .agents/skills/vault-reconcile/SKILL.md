# Vault Reconcile

Keep live task state and durable context consistent without turning the vault into a transcript archive.

1. Read the vault's own guidance, canonical task list, relevant project hub, and today's daily note before editing.
2. Search for the task/topic and reuse the canonical note. Do not create a parallel general TODO or duplicate an existing task.
3. For a new commitment, add one item in the configured capture state unless the user assigned a state. For current work, respect the work-in-progress limit and existing priority rules.
4. Move a task between states rather than copying it. A blocker records the factual reason, dependency, and next review date or trigger. Completion requires observable evidence and a date.
5. Keep granular work in the project backlog; the general list holds the outcome, one concrete next action, and a source link.
6. Log material facts, decisions, evidence, and next action in today's daily note using local time. Preserve any required final inbox section.
7. Promote only durable concepts, decisions, runbooks, or postmortems into atomic notes. Link new notes from the vault index and relevant project hub.
8. Never write secret values, raw private conversations, or unnecessary personal/customer data. Verify the final note structure and updated metadata.

Do not start or continue unrelated tasks merely because they appear in the task list. Report the exact state movements and notes updated.
