# Slopsquatting at Scale: Spracklen et al. USENIX 2025

The definitive numbers on package-name hallucination, from [Spracklen et al., USENIX Security 2025](https://socket.dev/blog/slopsquatting-how-ai-hallucinations-are-fueling-a-new-class-of-supply-chain-attacks). 576,000 code samples across 16 LLMs.

## Headline numbers

- **19.7% of suggested packages do not exist** — 205,474 unique fake names
- **Open-source models hallucinate at 21.7%**; commercial (GPT-4 class) at **5.2%**
- **43% of hallucinations are repeatable** across re-runs (same fake name appears 10/10 times for 43% of cases; >1× for 58%)
- **8.7% of hallucinated Python packages are real npm names** — cross-language confusion creates dependency-confusion vectors

## Why repeatability matters

Repeatable hallucinations make **registration attacks economically viable**. An attacker only needs to register the fake name once on PyPI/npm; victims then `pip install` it via copy-pasted LLM output.

## Defensive guidance

- Lock dependencies with hash-pinning (pip `--require-hashes`, npm `package-lock.json` integrity)
- Run private package registry mirrors with explicit allowlist
- Use SCA tools that flag low-reputation packages
