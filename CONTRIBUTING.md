# Contributing

This is a private collaboration repository.

1. Keep changes generic and remove real account, project, customer, infrastructure, wallet, and message data.
2. Preserve attribution and private sharing terms.
3. Add project-specific material only in your own downstream repository or private vault.
4. Run `bash scripts/verify-all.sh` and review the full staged diff.
5. Use a focused branch/commit for a coherent change.
6. Explain any time-sensitive claim and link its current primary source.

A change that weakens a security gate must include the explicit reason, risk, and replacement control.

Never request a repository/provider credential in an issue or pull request. Use the reviewed `secenv ask` + Can Workbench flow after the operation and minimum permissions are defined.
